# 🎯 SPb Lead Bot — Поиск клиентов на разработку сайтов в Санкт-Петербурге

Приватный Telegram-бот для поиска, скоринга и квалификации заведений Санкт-Петербурга, которым потенциально нужна разработка или починка сайта.

## 🚀 Возможности
- Автоматический сбор по расписанию (по умолчанию раз в сутки в 04:00 МСК) и выдача накопленных лидов пачками по кнопке «📦 Следующие 30» со статусами «Написал», «Ответили», «Отказ», «Нет ответа» (подробности в разделе ниже).
- Бесплатный парсинг районов СПб через OpenStreetMap (Overpass API, с запасным сервером) + поддержка 2GIS API 3.0 (постранично, до 10 страниц / 500 мест за сбор — каждая страница расходует квоту ключа). OSM и 2GIS опрашиваются параллельно.
- Импорт CSV-выгрузок из десктопных парсеров Яндекс Карт и 2ГИС (до 2000 записей за файл).
- Склейка дубликатов: одна организация из OSM, 2GIS и CSV (общий телефон, то же название и адрес или то же название в пределах 150 м) сохраняется один раз, недостающие контакты дополняются из другого источника.
- Автоматический HTTP-чекер сайтов:
  - `dead_site` — в карточке указан домен, но сайт не работает (ошибка HTTP вроде 404, 410 или 5xx, истёк домен, упал SSL, нет ответа за 20 с). Ответы 401/403/429 (защита от ботов, авторизация, лимит запросов) означают, что сайт жив. Адрес без схемы проверяется по `https://`, а при неудаче — по `http://`.
  - `social_only` — вместо сайта ссылка на соцсеть или агрегатор (VK, Telegram, WhatsApp, Instagram, Taplink, YClients, Dikidi, Linktree).
  - `no_site` — сайт отсутствует, но есть телефон или соцсети для связи.
  - Проверка не обращается к `localhost`, внутренним сетям и адресам метаданных облака (защита от SSRF), в том числе через редиректы.
- Скоринг (0–100 баллов) с учётом маржинальности ниши и полноты контактов (правила — в `docs/SPEC.md`).
- Мини-CRM внутри Telegram (`Новые`, `В работе`, `В отказе`) + генерация шаблона первого сообщения для клиента. Во время сбора в сообщении обновляется прогресс «Проверено сайтов: N/M».
- Выгрузка лидов в CSV для Excel (разделитель `;`, дата добавления по московскому времени).

## 🛠 Быстрый старт

1. Создайте виртуальное окружение (целевая версия — Python 3.11, как в Docker-образе) и установите зависимости:

    python -m venv .venv
    source .venv/bin/activate
    pip install -r requirements-dev.txt

   Для парсера 2ГИС нужен ещё браузер (в Docker-образ он не входит, поэтому в контейнере парсер не запустится и сообщит об этом):

    playwright install chromium

   Файлы зависимостей:
   - `requirements.txt` — прямые зависимости бота с закреплёнными версиями;
   - `requirements-dev.txt` — то же плюс pytest, mypy и ruff (для разработки и CI);
   - `requirements.lock` — полный закреплённый набор для Docker-образа. После изменения `requirements.txt` пересоберите его командой `python scripts/lock_requirements.py`.

2. Скопируйте `.env.example` в `.env` и укажите `BOT_TOKEN` и ваш `ADMIN_TG_ID` (остальные настройки — в таблице выше).
3. Запустите бота:

    python main.py

4. Тесты (сеть не используется):

    pytest

5. Линтер и проверка типов (настройки в `ruff.toml` и `mypy.ini`):

    ruff check .
    mypy

   Те же проверки и тесты запускает CI (`.github/workflows/ci.yml`) на Python 3.11 с версиями из `requirements.lock` при каждом push в `main` и pull request.

### Запуск в Docker

    docker compose up -d --build

База хранится в каталоге `./db` (`./db/leads.db`), Docker создаст его сам. В контейнере `DB_URL` задаётся в `docker-compose.yml` и перекрывает значение из `.env`.

Бот работает в контейнере не от root, а от пользователя `app` (UID/GID `1000` по умолчанию). При старте entrypoint (`docker_entrypoint.py`) делает владельцем `./db` и файлов в нём этого пользователя. Если на Linux-хосте ваш UID не `1000`, укажите свой, чтобы база оставалась доступной вам без `sudo`:

    APP_UID=$(id -u) APP_GID=$(id -g) docker compose up -d --build

(или пропишите `APP_UID` и `APP_GID` в `.env`).

**Переход со старой схемы** (раньше монтировался файл `./leads.db` в корне проекта). Без переноса бот стартует с пустой базой, а старые лиды останутся нетронутыми в `./leads.db`:

    docker compose down
    mkdir -p db
    mv leads.db db/leads.db
    docker compose up -d --build

Если `./leads.db` оказался пустым каталогом (так Docker поступал, когда файла не было), удалите его: `rmdir leads.db`.

## 📦 Автосбор и выдача лидов

Бот сам копит лиды в базе, а вы забираете их пачками и связываетесь с организациями.

1. **Сбор** идёт по расписанию (`COLLECT_CRON`, по умолчанию `0 4 * * *`), параллельных запусков не бывает. Сохраняются только организации без рабочего сайта (те же проверка сайта и скоринг, что и при ручном поиске). После сбора приходит короткий итог без звука, и только если появились новые лиды.
2. **Если новых лидов меньше `LEADS_MIN_POOL`** (по умолчанию 60), бот запускает внеочередной сбор. Запас проверяется каждые 15 минут и после каждой выдачи; внеочередной сбор идёт не чаще раза в час.
3. **Кнопка «📦 Следующие 30»** (или `/next_leads`) выдаёт самые старые новые лиды, и они получают статус «выдан». Нажатие работает только с базой, к внешним источникам бот в этот момент не обращается. Каждый лид приходит отдельным сообщением с кнопками «Написал», «Ответили», «Отказ», «Нет ответа»; результат сохраняется в поле `contact_status`, его можно менять. Сообщения идут по одному в секунду, поэтому пачка из 30 лидов приходит примерно за 30 секунд. Пока пачка отправляется, повторное нажатие новую не выдаёт. Если Telegram не принял сообщение, лид возвращается в запас.
4. **Если новых лидов меньше размера пачки,** бот выдаёт сколько есть и запускает сбор в фоне (с учётом ограничения раз в час и суточного лимита), о чём сообщает.

Выданный лид больше не выдаётся и не перезаписывается, даже если организация снова найдена при сборе.

После обновления отправьте боту `/start`, чтобы на клавиатуре появилась новая кнопка.

### Команды

| Команда | Что делает |
|---|---|
| `/next_leads` | То же, что кнопка «📦 Следующие 30» |
| `/chat_id` | Показать ID текущего чата, для `NOTIFY_CHAT_IDS` |
| `/leads_stats` | Сколько всего лидов, в запасе, выдано, написал, ответили, отказ, нет ответа; выгрузка всех лидов в CSV |
| `/provider_on [источник]` | Включить источник после автоматического отключения и сбросить счётчик блокировок (по умолчанию `2gis_scraper`) |
| `/collect_now` | Запустить сбор сейчас, итог придёт сообщением |
| `/collect_status` | Расписание, состояние источников (работает, пауза, отключён), следующий запуск, результат последнего запуска, расход запросов |
| `/collect_on`, `/collect_off` | Включить или выключить автосбор (и расписание, и пополнение запаса), выбор сохраняется в базе. Ручной `/collect_now` работает всегда. При `COLLECT_ENABLED=false` эти команды только сообщают, что сбор идёт на внешнем сборщике |

### Настройки автосбора

| Переменная | По умолчанию | Описание |
|---|---|---|

| `COLLECT_CRON` | `0 4 * * *` | Расписание в формате crontab: минута, час, день, месяц, день недели (0 и 7 — воскресенье) |
| `COLLECT_INTERVAL_MINUTES` | не задан | Интервал в минутах; если задан, заменяет `COLLECT_CRON`. Отсчёт идёт от запуска бота |
| `COLLECT_TIMEZONE` | `Europe/Moscow` | Часовой пояс расписания |

| `COLLECT_PROVIDERS` | `osm` | Источники по порядку приоритета: `osm`, `2gis` (API, нужен ключ; если указан и парсер, работает только пока тот недоступен), `2gis_scraper` (парсер, см. ограничения ниже), `yandex` (заглушка) |
| `COLLECT_QUERIES` | все ниши | Через запятую: ключи ниш (`dentist_clinic`, `auto_repair`, `beauty`, `legal_b2b`, `horeca`, `hotels`) и/или свои запросы (`кондитерская`). Свои запросы работают только в 2ГИС |
| `COLLECT_DISTRICTS` | все районы | Районы СПб через запятую |
| `COLLECT_BBOX` | не задан | Своя область вместо районов: `юг,запад,север,восток`. В OSM и 2ГИС ищется только внутри неё |
| `COLLECT_MAX_PAGES` | `2` | Страниц на одну пару «ниша + район» |
| `COLLECT_PAGE_SIZE` | `50` | Размер страницы 2ГИС; для демо-ключа укажите `10` |
| `COLLECT_MAX_RESULTS_PER_QUERY` | `100` | Результатов на одну пару «ниша + район» |
| `COLLECT_MAX_REQUESTS_PER_RUN` | `60` | Запросов ко всем API за один сбор. Следующий сбор продолжит с места остановки |
| `COLLECT_MAX_REQUESTS_PER_DAY` | `200` | Запросов ко всем API за сутки (в часовом поясе расписания). Сутки считаются и для `/collect_now` |
| `SCRAPER_CITY_SLUG` | `spb` | Город в адресах 2ГИС. `COLLECT_BBOX` на парсер не влияет: он ищет по тексту запроса и району |
| `SCRAPER_MIN_DELAY_SECONDS`, `SCRAPER_MAX_DELAY_SECONDS` | `3`, `8` | Случайная пауза между страницами, минимум 3 секунды |
| `SCRAPER_MAX_PAGES_PER_RUN` | `200` | Страниц за запуск, считая карточки организаций (до 500) |
| `SCRAPER_MAX_RESULTS_PER_RUN` | `300` | Организаций за запуск (до 500) |
| `SCRAPER_MIN_HOURS_BETWEEN_RUNS` | `20` | Сайт посещается не чаще этого, в том числе при внеочередных сборах и `/collect_now` |
| `SCRAPER_BLOCK_BACKOFF_HOURS` | `6` | Пауза после блокировки, удваивается при каждой следующей подряд |

### Парсер 2ГИС: ограничения

По умолчанию парсер выключен и на сайт 2ГИС не обращается. Чтобы включить его, укажите `COLLECT_PROVIDERS=2gis_scraper,osm` и прочитайте этот раздел.

> **Текущее состояние: парсер не приносит данных.** При проверке 5 ноября 2026 первый же запрос браузера получил капчу (`captcha.2gis.ru`, reCAPTCHA, «Мы заметили подозрительную активность с вашего IP адреса»). Поэтому настоящих страниц поиска никто не видел: адреса и формат данных в `src/services/scraper/twogis_site.py` взяты из документации API и не проверены на сайте. Пока сайт отвечает капчей, бот останавливает парсер, сообщает об этом и после трёх блокировок подряд отключает его. Лиды продолжают приходить из других источников.

**Условия 2ГИС.** Парсер работает с публичными страницами, но [лицензионное соглашение 2ГИС](https://law.2gis.ru/licensing-agreement) запрещает это прямо: п. 5.1.8 запрещает «любые автоматические и автоматизированные запросы», скрипты и ботов «для сбора, выгрузки и (или) передачи каких-либо данных», если это не разрешено соглашением; п. 5.1.4 и 5.2 запрещают извлечение и коммерческое использование справочных данных. **Использование парсера нарушает эти условия и остаётся на ответственности владельца проекта.** 2ГИС может заблокировать доступ и преследовать нарушение прав (п. 8.6, 8.7). Перед использованием стоит посоветоваться с юристом или запросить разрешение у 2ГИС.

**Что парсер делает и чего не делает:**
- Читает JSON, который страница получает сама, и не разбирает вёрстку: селекторы не на чем проверить.
- Берёт только данные организаций: название, адрес, телефоны, сайт, публичный email, координаты, ссылку на карточку. Рубрикой служит ниша из запроса. Отзывы и фото не собираются.
- Открывает одну страницу за раз со случайной паузой 3–8 секунд, не чаще одного сбора в сутки, с лимитом страниц и организаций за запуск.
- Соблюдает `robots.txt`: если страница запрещена или файл нельзя прочитать, парсер не начинает работу.
- Использует стандартный User-Agent браузера, в котором видно `HeadlessChrome`.
- **Не решает капчу, не использует прокси, не подменяет отпечатки браузера и не обходит защиту.** Добавлять это нельзя.

**Что происходит при капче, ответах 401/403/429 или нераспознанной странице:**
1. Парсер сразу останавливается, бот пишет в лог и сообщает администраторам. Найденное до этого сохраняется.
2. Следующая попытка не раньше чем через 6 часов, затем через 12.
3. После трёх блокировок подряд парсер отключается до команды `/provider_on 2gis_scraper`. Успешный запуск обнуляет счётчик.

Пока парсер на паузе или отключён, работают остальные источники из `COLLECT_PROVIDERS`, включая API 2ГИС, если он указан и задан ключ. Если парсер просто ждёт следующих суток, платный API не используется.

Браузер закрывается после каждого запуска, в том числе при ошибке и остановке бота. При изменении сайта парсер потребует доработки: всё, что зависит от сайта, находится в `src/services/scraper/twogis_site.py`.

### Ключ 2ГИС

Необязательный источник. Ключ создаётся в [кабинете Platform Manager](https://docs.2gis.com/platform-manager/subscription/keys) и прописывается в `DGIS_API_KEY`. Для автосбора добавьте `2gis` в `COLLECT_PROVIDERS`, например `2gis,osm`. Если `2gis` указан, а ключа нет, бот работает как обычно: API отключается, причина видна в логе и в `/collect_status`.

**Важно проверить до использования:**
- Контакты (`items.contact_groups`) [предоставляются отдельно и за доплату](https://docs.2gis.com/en/api/search/places/overview) через отдел продаж 2ГИС. Без них организации приходят без телефона и сайта и не проходят скоринг. Бот заметит такую выдачу и один раз пришлёт предупреждение.
- [Демо-ключ](https://docs.2gis.com/platform-manager/subscription/keys) действует месяц: не больше 1000 запросов на сервис, 5 страниц по 10 объектов, контактов нет. При превышении лимита ключ блокируется до начала следующего месяца, поэтому сверьте `COLLECT_MAX_REQUESTS_PER_DAY` со своим тарифом.

Ошибки ключа и квоты останавливают обращения к 2ГИС до следующего сбора, а администраторам приходит одно сообщение на одну и ту же проблему. Временные ошибки (сеть, 5xx, 429) повторяются до 3 раз с растущей паузой.

### Яндекс

Провайдер Яндекса оставлен заглушкой (`src/services/providers/yandex.py`), запросы к Яндексу бот не отправляет. [Условия API](https://yandex.ru/dev/tariffs/doc/ru/geosearch/terms/) разрешают кэшировать ответы не дольше 30 дней и показывать данные только на фоне Яндекс Карт, а бот хранит лиды бессрочно и отправляет их в Telegram.

### Обновление схемы базы и откат

Новые колонки `leads.email`, `leads.source_url`, `leads.issued_at`, `leads.contact_status`, `leads.contact_status_by_id`, `leads.contact_status_by`, `leads.contact_status_at`, `leads.exported_at`, `leads.imported_at`, индекс и таблицы `collector_state`, `provider_state`, `import_log` появляются сами при запуске бота, существующие лиды не меняются и попадают в очередь выдачи. Перед обновлением сделайте копию файла базы.

Старая версия бота работает с обновлённой базой без изменений, но не покажет новые статусы в своих счётчиках. Чтобы полностью убрать изменения (SQLite 3.35+), остановите бота и выполните:

    UPDATE leads SET crm_status = 'rejected' WHERE contact_status = 'rejected';
    UPDATE leads SET crm_status = 'in_work' WHERE crm_status = 'issued';
    DROP INDEX ix_leads_crm_status_created_at;
    ALTER TABLE leads DROP COLUMN email;
    ALTER TABLE leads DROP COLUMN source_url;
    ALTER TABLE leads DROP COLUMN issued_at;
    ALTER TABLE leads DROP COLUMN contact_status;
    ALTER TABLE leads DROP COLUMN contact_status_by_id;
    ALTER TABLE leads DROP COLUMN contact_status_by;

## 🏠 Сбор на домашнем компьютере

    компьютер: collect_cli.py → exports/leads_*.json → файл боту или scp → сервер: импорт → «📦 Следующие 30»

Парсер запускается на вашем компьютере и кладёт лиды в файл, а сервер их импортирует. Бот на сервере при этом сам ничего не собирает.

> **Прочитайте раздел «Парсер 2ГИС: ограничения».** Перенос на домашний компьютер не отменяет условий 2ГИС: п. 5.1.8 лицензионного соглашения запрещает автоматизированный сбор, ответственность на владельце проекта, а блокироваться теперь будет ваш домашний IP. Домашний адрес тоже не гарантирует отсутствия капчи: при проверке 5 ноября 2026 с компьютера разработчика первый же запрос получил капчу, и данные страниц 2ГИС ни разу не проверялись на реальном ответе. Если сайт откажет, сборщик остановится и сообщит об этом.

### Установка сборщика на Windows

1. Установите [Python 3.11 или новее](https://www.python.org/downloads/), отметив «Add python.exe to PATH».
2. Откройте PowerShell в папке проекта:

       python -m venv .venv
       .venv\Scripts\python -m pip install -r requirements.txt
       .venv\Scripts\python -m playwright install chromium

3. Создайте в папке проекта файл `.env`. Токен и ID администратора здесь не нужны:

       COLLECTOR_PROVIDERS=2gis_scraper
       COLLECT_QUERIES=dentist_clinic,auto_repair,beauty
       COLLECT_DISTRICTS=Центральный,Петроградский
       SCRAPER_MAX_RESULTS_PER_RUN=300

На Linux и macOS всё то же самое, только пути `.venv/bin/python`.

### Запуск вручную

    .venv\Scripts\python collect_cli.py

| Запуск | Что делает |
|---|---|
| `collect_cli.py` | Собирает и пишет новые лиды в `exports/leads_ГГГГММДД_ЧЧММСС.json` |
| `collect_cli.py --no-export` | Только собирает |
| `collect_cli.py --export-only` | Только выгружает накопленное, браузер не запускается |
| `collect_cli.py --enable-provider 2gis_scraper` | Снимает автоотключение и паузу после блокировок (то же, что `/provider_on` у бота) |

Каждый лид попадает в файл один раз. Сборщик хранит состояние в своей базе `data/collector.db`, в том числе счётчик блокировок и время паузы, и не трогает базу бота.

Код возврата: `0` выполнено, `1` ошибка, `2` источник отказал или ждёт после отказа, `130` прервано.

### Запуск по расписанию

Рекомендуемая частота: **раз в сутки**. Запускать чаще бессмысленно: сборщик не откроет сайт раньше, чем пройдёт `SCRAPER_MIN_HOURS_BETWEEN_RUNS` (20 часов).

**Планировщик заданий Windows.** Создайте задание: триггер «Ежедневно», действие «Запуск программы», программа — полный путь к `run_collector.bat`. Или из командной строки:

    schtasks /Create /TN "spb-lead-collector" /SC DAILY /ST 09:00 /TR "C:\путь\к\проекту\run_collector.bat"

В параметрах задания оставьте «Не запускать новый экземпляр». Скрипт дописывает вывод в `logs\collector.log`. Для запуска из консоли с выводом на экран есть `run_collector.ps1`:

    powershell -ExecutionPolicy Bypass -File .\run_collector.ps1

**Linux и macOS (cron):**

    0 9 * * * cd /путь/к/проекту && .venv/bin/python collect_cli.py >> logs/collector.log 2>&1

Создайте папку `logs` заранее.

### Что делать при капче

Сборщик сам остановится, напишет «капча, повтор не раньше ...» и завершится с кодом `2`.

- **Подождите и не запускайте сбор повторно.** Паузы 6 и 12 часов сборщик выдерживает сам, ранний запуск просто ничего не сделает.
- После трёх блокировок подряд источник отключится. Включайте его командой `--enable-provider`, только если проблема решена.
- Не пытайтесь обойти защиту. Форма на странице капчи ведёт в поддержку 2ГИС: [help.2gis.ru/feedback](https://help.2gis.ru/feedback/). Законный путь получить данные — их платный API с контактами.

### Перенос файла на сервер

**Способ 1. Отправить файл боту** в личку или в группу. Принимаются только `.json` от администраторов из `ADMIN_TG_ID` и `ADMIN_TG_IDS`. При включённом privacy mode бот не видит файлы в группе, если это не ответ на его сообщение, поэтому проще отправить в личку.

**Способ 2. Скопировать в папку на сервере.** Бот проверяет её раз в `IMPORT_INBOX_INTERVAL_SECONDS` (5 минут) и берёт файлы, которые не менялись последние 30 секунд:

    scp exports\leads_20261105_090000.json user@server:/путь/к/проекту/data/inbox/

Обработанный файл переезжает в `data/inbox/done/`, а не прошедший проверку — в `data/inbox/failed/` вместе с файлом `.reason.txt` с причиной. В Docker папка находится в `./db/inbox`.

### Настройка сервера

    COLLECT_ENABLED=false
    LEADS_MIN_POOL=60

- Сервер не запускает сбор. `/collect_now` и кнопка «▶️ Запустить сбор» сообщают, что сбор идёт на внешнем сборщике.
- Когда новых лидов меньше `LEADS_MIN_POOL`, бот просит загрузить новый файл, не чаще раза в сутки.
- Итог импорта приходит в `NOTIFY_CHAT_IDS` и админам: сколько в файле, новых, дубликатов, отклонено и почему. `/collect_status` показывает последний импорт, сколько лидов пришло файлами и сколько в запасе.

Новый порт на сервере не открывается: файл приходит через Telegram или ваш SSH.

### Правила импорта

- Записи проходят те же проверки, что и обычный сбор: уникальность по источнику и его ID, телефону, названию и адресу, проверка сайта и оценка. Сайт сервер проверяет заново, поэтому импорт большого файла занимает несколько минут.
- Нужен телефон или сайт. Организации с рабочим сайтом не сохраняются.
- Лиды, уже известные боту (в том числе выданные и обработанные), не меняются. Повторная загрузка того же файла ничего не добавляет.
- Плохая запись отклоняется с подсчётом причины, остальные импортируются. Файл целиком отклоняется, если он повреждён, больше `IMPORT_MAX_FILE_BYTES`, содержит больше `IMPORT_MAX_LEADS` записей, имеет другую версию схемы или контрольная сумма не совпала.

### Формат файла

```json
{
  "schema_version": 1,
  "exported_at": "2026-11-05T09:00:00+03:00",
  "source_host": "HOME-PC",
  "count": 1,
  "checksum": "sha256 от списка leads",
  "leads": [{
    "source": "2gis", "source_id": "70000001", "name": "Улыбка, стоматология",
    "address": "Невский проспект, 10", "city": "Санкт-Петербург",
    "phones": ["+78125550101"], "website": "smile.example", "email": null,
    "rubric": "dentist_clinic", "lat": 59.935, "lon": 30.325,

    "socials": [], "district": "Центральный"

```

Только публичные данные организаций, без токенов и настроек. Обязательны `schema_version`, `leads`, а в записи `source`, `source_id`, `name`; `count` и `checksum` проверяются, если указаны. Город не сохраняется: бот работает с одним городом.

## 👥 Работа в группе

Бот может работать в группе: присылать туда итоги сбора и выдавать лиды прямо в чат. Личка при этом работает как раньше.

**Настройка:**
1. Создайте группу в Telegram (или возьмите существующую).
2. Добавьте в неё бота и разрешите ему писать сообщения, если в группе это ограничено.
3. Отправьте в группе `/chat_id` от имени администратора бота, он ответит ID чата. ID групп отрицательные, у супергрупп они начинаются с `-100`.
4. Укажите ID в `.env`, несколько групп через запятую, и перезапустите бота:

       NOTIFY_CHAT_IDS=-1001234567890,-1009876543210
       NOTIFY_ADMINS_PRIVATE=true

5. Отправьте в группе `/start`: появятся кнопки «📦 Следующие 30», «📊 Статистика», «🤖 Статус сбора», «▶️ Запустить сбор».

`NOTIFY_CHAT_IDS` отвечает только за уведомления. Кнопки и команды работают в любой группе, куда добавлен бот, но итог сбора приходит по этому списку, а не в чат, где сбор запустили. Поэтому группу, откуда запускаете сбор, тоже стоит указать здесь.

**Privacy mode отключать не нужно.** С включённым режимом (по умолчанию) бот видит команды, в том числе `/cmd@имя_бота`, и нажатия на кнопки под сообщениями, этого достаточно. Если в группе несколько ботов, пишите команды с именем бота: Telegram может не доставить `/cmd` без него. Отключить режим (@BotFather → `/setprivacy` → Disable, затем удалить бота из группы и добавить снова) нужно, только чтобы работал текстовый ввод «📦 Следующие 30», меню «📋 Новые лиды» и загрузка CSV в группе. Тогда бот будет получать все сообщения группы, но реагировать только на свои команды.

**Кто что может:**
- Управляют ботом только пользователи из `ADMIN_TG_ID` и `ADMIN_TG_IDS`, проверяется тот, кто нажал или написал. Быть администратором группы для этого не нужно и недостаточно.
- Остальные на нажатие кнопки получают всплывающее «⛔ Нет доступа», на команду — короткий ответ не чаще раза в 5 минут. Обычные сообщения бот не замечает.
- Администратор группы, включивший в Telegram режим «анонимно», для бота не определяется и получит отказ.

**Что важно знать:**
- **Контакты лидов видны всем участникам группы:** карточки уходят в тот чат, где нажата кнопка. Выдавайте лиды только в группе, где это допустимо.
- Telegram разрешает боту не больше 20 сообщений в минуту в группу, поэтому карточки идут с паузой 3,1 с, и пачка из 30 приходит примерно за полторы минуты. Пока пачка отправляется, новая в этом чате не начнётся. Из разных чатов лиды не пересекаются.
- На карточке видно, кто поставил статус: «✍️ Написал — @username». Кто и когда отметил, есть и в выгрузке CSV.
- Если группа стала супергруппой, у неё меняется ID. Бот заметит это при отправке, продолжит писать по новому ID до перезапуска и сообщит его в лог и в чат. Замените ID в `NOTIFY_CHAT_IDS`.
- Ошибка отправки в один чат не мешает остальным и не прерывает сбор.

## 📥 Формат CSV для ручного импорта
Бот поддерживает загрузку `.csv` файлов (разделитель `,` или `;`, кодировка `UTF-8` или `Windows-1251`, до 2000 записей — остальные бот пропустит и сообщит, сколько). Распознаются колонки:
- `name` / `Название` / `Имя`
- `category` / `Рубрика` / `Категория`
- `district` / `Район`
- `address` / `Адрес`
- `phone` / `Телефон` / `Телефоны`
- `website` / `Сайт` / `Web`
- `socials` / `ВК` / `VK` / `Telegram`
