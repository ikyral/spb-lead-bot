# 🎯 SPb Lead Bot — Поиск клиентов на разработку сайтов в Санкт-Петербурге

Приватный Telegram-бот для поиска, скоринга и квалификации заведений Санкт-Петербурга, которым потенциально нужна разработка или починка сайта.

## 🚀 Возможности
- Автоматический сбор по расписанию (по умолчанию раз в сутки в 04:00 МСК) и выдача накопленных лидов пачками по кнопке «📦 Следующие 30» со статусами «Написал», «Ответили», «Отказ», «Нет ответа» (подробности в разделе ниже).
- Основной источник: 2GIS API 3.0, работает и без доступа к контактам (см. «Лиды без контактов»). Дополнительно: бесплатный парсинг районов СПб через OpenStreetMap (Overpass API, с запасным сервером) + 2GIS API 3.0 (постранично, до 10 страниц / 500 мест за сбор — каждая страница расходует квоту ключа). OSM и 2GIS опрашиваются параллельно.
- Импорт CSV-выгрузок из десктопных парсеров Яндекс Карт и 2ГИС (до 2000 записей за файл).
- Склейка дубликатов: одна организация из OSM, 2GIS и CSV (общий телефон, то же название и адрес или то же название в пределах 150 м) сохраняется один раз, недостающие контакты дополняются из другого источника.
- Автоматический HTTP-чекер сайтов:
  - `dead_site` — в карточке указан домен, но сайт не работает (ошибка HTTP вроде 404, 410 или 5xx, истёк домен, упал SSL, нет ответа за 20 с). Ответы 401/403/429 (защита от ботов, авторизация, лимит запросов) означают, что сайт жив. Адрес без схемы проверяется по `https://`, а при неудаче — по `http://`.
  - `social_only` — вместо сайта ссылка на соцсеть или агрегатор (VK, Telegram, WhatsApp, Instagram, Taplink, YClients, Dikidi, Linktree).
  - `no_site` — сайт отсутствует, но есть телефон или соцсети для связи.
  - Проверка не обращается к `localhost`, внутренним сетям и адресам метаданных облака (защита от SSRF), в том числе через редиректы.
- Скоринг (0–100 баллов) с учётом маржинальности ниши и полноты контактов (правила — в `docs/SPEC.md`).
- Мини-CRM внутри Telegram (`Новые`, `В работе`, `В отказе`) + генерация шаблона первого сообщения для клиента. Во время сбора в сообщении обновляется прогресс «Проверено сайтов: N/M».
- Выгрузка лидов в CSV для Excel (разделитель `;`, дата добавления по московскому времени).

## 🛠 Быстрый старт

1. Создайте виртуальное окружение (целевая версия — Python 3.11, как в Docker-образе) и установите зависимости:

    python -m venv .venv
    source .venv/bin/activate
    pip install -r requirements-dev.txt

   Для парсера 2ГИС нужен ещё браузер (в Docker-образ он не входит, поэтому в контейнере парсер не запустится и сообщит об этом):

    playwright install chromium

   Файлы зависимостей:
   - `requirements.txt` — прямые зависимости бота с закреплёнными версиями;
   - `requirements-dev.txt` — то же плюс pytest, mypy и ruff (для разработки и CI);
   - `requirements.lock` — полный закреплённый набор для Docker-образа. После изменения `requirements.txt` пересоберите его командой `python scripts/lock_requirements.py`.

2. Скопируйте `.env.example` в `.env` и укажите `BOT_TOKEN` и ваш `ADMIN_TG_ID` (остальные настройки — в таблице выше).
3. Запустите бота:

    python main.py

4. Тесты (сеть не используется):

    pytest

5. Линтер и проверка типов (настройки в `ruff.toml` и `mypy.ini`):

    ruff check .
    mypy

   Те же проверки и тесты запускает CI (`.github/workflows/ci.yml`) на Python 3.11 с версиями из `requirements.lock` при каждом push в `main` и pull request.

### Запуск в Docker

    docker compose up -d --build

База хранится в каталоге `./db` (`./db/leads.db`), Docker создаст его сам. В контейнере `DB_URL` задаётся в `docker-compose.yml` и перекрывает значение из `.env`.

Бот работает в контейнере не от root, а от пользователя `app` (UID/GID `1000` по умолчанию). При старте entrypoint (`docker_entrypoint.py`) делает владельцем `./db` и файлов в нём этого пользователя. Если на Linux-хосте ваш UID не `1000`, укажите свой, чтобы база оставалась доступной вам без `sudo`:

    APP_UID=$(id -u) APP_GID=$(id -g) docker compose up -d --build

(или пропишите `APP_UID` и `APP_GID` в `.env`).

**Переход со старой схемы** (раньше монтировался файл `./leads.db` в корне проекта). Без переноса бот стартует с пустой базой, а старые лиды останутся нетронутыми в `./leads.db`:

    docker compose down
    mkdir -p db
    mv leads.db db/leads.db
    docker compose up -d --build

Если `./leads.db` оказался пустым каталогом (так Docker поступал, когда файла не было), удалите его: `rmdir leads.db`.

## 📦 Автосбор и выдача лидов

Бот сам копит лиды в базе, а вы забираете их пачками и связываетесь с организациями.

1. **Сбор** идёт по расписанию (`COLLECT_CRON`, по умолчанию `0 4 * * *`), параллельных запусков не бывает. Сохраняются организации без рабочего сайта (те же проверка сайта и скоринг, что и при ручном поиске) и организации из 2ГИС без контактов, см. «Лиды без контактов». После сбора приходит короткий итог без звука, и только если появились новые лиды.
2. **Если новых лидов меньше `LEADS_MIN_POOL`** (по умолчанию 60), бот запускает внеочередной сбор. Запас проверяется каждые 15 минут и после каждой выдачи; внеочередной сбор идёт не чаще раза в час.
3. **Кнопка «📦 Следующие 30»** (или `/next_leads`) выдаёт новые лиды в порядке уверенности, что сайт нужен, см. «Нужен ли сайт». Лиды получают статус «выдан». Нажатие работает только с базой, к внешним источникам бот в этот момент не обращается. Каждый лид приходит отдельным сообщением с кнопками «Написал», «Ответили», «Отказ», «Нет ответа»; результат сохраняется в поле `contact_status`, его можно менять. Сообщения идут по одному в секунду (ограничение Telegram), поэтому пачка из 30 лидов приходит примерно за 30 секунд. Бот сразу отвечает на нажатие «⏳ Выдаю лиды…», а карточки отправляет в фоне, не задерживая другие команды. Пока пачка отправляется, повторное нажатие новую не выдаёт. Если бот перезапускается посреди пачки, неотправленные лиды возвращаются в запас. Если Telegram не принял сообщение, лид возвращается в запас.
4. **Если новых лидов меньше размера пачки,** бот выдаёт сколько есть и запускает сбор в фоне (с учётом ограничения раз в час и суточного лимита), о чём сообщает.

Выданный лид больше не выдаётся и не перезаписывается, даже если организация снова найдена при сборе.

После обновления отправьте боту `/start`, чтобы на клавиатуре появилась новая кнопка.

### Меню и подсказки

В личке у администратора внизу четыре кнопки: «📦 Следующие 30», «🔎 Обогащение» (пошаговая инструкция с командой для терминала и кнопкой «📄 Получить файл запроса», то же, что `/export_unknown 30`), «📊 Ниши и статистика» (`/leads_stats` и `/niches`) и «❓ Помощь» (`/help`: команды по разделам с примерами). В группе эта клавиатура не появляется, там остаются кнопки под сообщением `/start`. Под ними прежние кнопки: «🔍 Поиск по СПб», «📋 Новые лиды», «💼 В работе», «📊 Статистика и CSV».

При старте бот задаёт меню команд Telegram: обычным пользователям только `/start` и `/help`, каждому администратору в его личке весь список. Если администратор ещё ни разу не писал боту, Telegram отвечает «chat not found»: это только запись в логе, меню появится после следующего перезапуска. На непонятный текст в личке бот отвечает «Не понял. Вот что можно:». Не-администратору на команду администратора приходит одно сообщение, что она недоступна (повторно не чаще раза в 5 минут). Права не изменились: всё, кроме `/start`, `/help` и этой подсказки, доступно только администраторам.

### Команды

| Команда | Что делает |
|---|---|
| `/start`, `/help` | О боте и главное меню; команды по разделам с примерами (доступны всем, админские команды видят только админы) |
| `/next_leads` | То же, что кнопка «📦 Следующие 30» |
| `/chat_id` | Показать ID текущего чата, для `NOTIFY_CHAT_IDS` |
| `/leads_stats` | Сколько всего лидов, в запасе, выдано, написал, ответили, отказ, нет ответа; запас по статусам сайта и нишам, сколько ждут проверки, сколько вердиктов «Сайт есть»; выгрузка всех лидов в CSV; запросы к API: сбор за сутки (2ГИС и OSM вместе), всего с ключом 2ГИС и сколько осталось по его лимиту |
| `/provider_on [источник]` | Включить источник после автоматического отключения и сбросить счётчик блокировок (по умолчанию `2gis`, если он включён, иначе `2gis_scraper`) |
| `/export_unknown [N] [ниша]` | Файл с лидами со статусом сайта `unknown` для сборщика (по умолчанию 30, максимум 60), сначала ниши, где сайта часто нет: см. «Какие ниши проверять первыми» |
| `/niches` | Таблица по нишам: проверено, без сайта, не открывается, с сайтом, осталось `unknown`, доля полезных |
| `/rescore` | Пересчитать оценки лидов в запасе по текущим весам и заново посчитать сети. Сами по себе старые лиды не пересчитываются |
| `/collect_now` | Запустить сбор сейчас, итог придёт сообщением |
| `/collect_status` | Расписание, состояние источников (работает, пауза, отключён), следующий запуск, результат последнего запуска, расход запросов к API 2ГИС и срок ключа, запас лидов с контактами и без, на сколько дней его хватит |
| `/collect_on`, `/collect_off` | Включить или выключить автосбор (и расписание, и пополнение запаса), выбор сохраняется в базе. Ручной `/collect_now` работает всегда. При `COLLECT_ENABLED=false` эти команды только сообщают, что сбор идёт на внешнем сборщике |

### Настройки автосбора

| Переменная | По умолчанию | Описание |

| `LEADS_ISSUE_UNKNOWN` | `true` | `false`: лиды со статусом сайта `unknown` не выдаются. С демо-ключом 2ГИС таких почти все |
| `LEADS_MAX_NICHE_SHARE` | `0.5` | Наибольшая доля одной ниши в пачке; `1` снимает ограничение. Если в запасе одна ниша, пачка будет неполной |
| `LEADS_CHAIN_MIN_BRANCHES` | `3` | С какого числа разных адресов с одним названием организация считается сетью |
| `LEADS_CHAIN_BLOCKLIST` | список в коде | Бренды через запятую, заменяют список из `src/services/chains.py` |
| `COLLECT_ENABLED` | `true` | `false` или пустой `COLLECT_PROVIDERS`: сервер сам не собирает, см. раздел «Сбор на домашнем компьютере» |
| `COLLECT_CRON` | `0 4 * * *` | Расписание в формате crontab: минута, час, день, месяц, день недели (0 и 7 — воскресенье) |
| `COLLECT_INTERVAL_MINUTES` | не задан | Интервал в минутах; если задан, заменяет `COLLECT_CRON`. Отсчёт идёт от запуска бота |
| `COLLECT_TIMEZONE` | `Europe/Moscow` | Часовой пояс расписания |
| `COLLECT_RUN_ON_START` | `false` | Запустить сбор сразу при старте бота, но только если за последние 20 часов не было успешного сбора и сбора по расписанию. Причина пропуска пишется в лог (`Collection at start skipped: …`). Сбор, пропущенный по расписанию (бот был выключен в это время), запускается при старте и без этого флага, тоже не чаще раза в 20 часов |
| `COLLECT_PROVIDERS` | `2gis,osm` | Источники по порядку приоритета: `2gis` (API, основной; без ключа пропускается), `osm`, `2gis_scraper` (парсер, по умолчанию выключен, см. ограничения ниже), `yandex` (заглушка) |
| `COLLECT_QUERIES` | все ниши | Через запятую: ключи ниш (см. «Ниши») и/или свои запросы (`кондитерская`). Свои запросы работают только в 2ГИС |
| `COLLECT_DISTRICTS` | все районы | Районы СПб через запятую |
| `COLLECT_BBOX` | не задан | Своя область вместо районов: `юг,запад,север,восток`. В OSM и 2ГИС ищется только внутри неё |
| `COLLECT_MAX_PAGES` | `2` | Страниц на одну пару «ниша + район» за один проход. API 2ГИС в следующий раз продолжает со следующей страницы |
| `COLLECT_RECHECK_DAYS` | `30` | Через сколько дней снова запрашивать у API 2ГИС пару «ниша + район», пройденную до конца |
| `COLLECT_PAGE_SIZE` | `50` | Размер страницы 2ГИС. С демо-ключом (`DGIS_DEMO_KEY=true`) автоматически снижается до `10` |
| `COLLECT_MAX_RESULTS_PER_QUERY` | `100` | Результатов на одну пару «ниша + район» |
| `COLLECT_MAX_REQUESTS_PER_RUN` | `60` | Запросов ко всем API за один сбор. Следующий сбор продолжит с места остановки |
| `COLLECT_MAX_REQUESTS_PER_DAY` | `200` | Запросов ко всем API за сутки (в часовом поясе расписания). Сутки считаются и для `/collect_now` |
| `SCRAPER_CITY_SLUG` | `spb` | Город в адресах 2ГИС, в том числе в ссылках на карточки. `COLLECT_BBOX` на парсер не влияет: он ищет по тексту запроса и району |
| `SCRAPER_MIN_DELAY_SECONDS`, `SCRAPER_MAX_DELAY_SECONDS` | `3`, `8` | Случайная пауза между страницами, минимум 3 секунды |
| `SCRAPER_MAX_PAGES_PER_RUN` | `200` | Страниц за запуск, считая карточки организаций (до 500) |
| `SCRAPER_MAX_RESULTS_PER_RUN` | `300` | Организаций за запуск (до 500) |
| `SCRAPER_MIN_HOURS_BETWEEN_RUNS` | `20` | Сайт посещается не чаще этого, в том числе при внеочередных сборах и `/collect_now`. `0` выключает интервал, в том числе для бота, если у него включён `2gis_scraper` |
| `SCRAPER_BLOCK_BACKOFF_HOURS` | `6` | Пауза после блокировки, удваивается при каждой следующей подряд |
| `SCRAPER_PAGE_TIMEOUT_SECONDS` | `45` | Таймаут загрузки страницы |
| `SCRAPER_HEADLESS` | `true` | `false` показывает окно браузера. Только для ручной отладки, не для расписания. Паузы, лимиты и остановка при капче работают так же |
| `SCRAPER_ASSISTED` | `false` | Сбор с участием человека, только в сборщике на компьютере: то же, что `--assisted`. Бот на сервере настройку не использует |
| `SCRAPER_PROFILE_DIR` | `data/browser_profile` | Папка профиля браузера с cookies для сбора с участием человека |
| `SCRAPER_ASSISTED_WAIT_MINUTES` | `5` | Сколько минут ждать, пока человек пройдёт капчу (до 30) |
| `SCRAPER_ASSISTED_MAX_CAPTCHAS` | `2` | Сколько раз за запуск можно просить пройти капчу (до 5) |

Неверное значение останавливает запуск бота с сообщением, в котором названа переменная.

### Парсер 2ГИС: ограничения

По умолчанию парсер выключен и на сайт 2ГИС не обращается. Чтобы включить его, укажите `COLLECT_PROVIDERS=2gis_scraper,osm` и прочитайте этот раздел.

> **Текущее состояние.** С сервера первый же запрос браузера получил капчу (`captcha.2gis.ru`, проверка 5 ноября 2026). С домашнего компьютера страницы открываются. 6 ноября 2026 формат проверен на одной странице поиска и шести карточках, четыре из них с сайтом: данные лежат в переменной страницы `initialState`, её и читает парсер. Обычный сбор парсером (поиск и карточки вместе) на сайте ещё не запускался. Пока сайт отвечает капчей, бот останавливает парсер, сообщает об этом и после трёх блокировок подряд отключает его. Лиды продолжают приходить из других источников.

**Условия 2ГИС.** Парсер работает с публичными страницами, но [лицензионное соглашение 2ГИС](https://law.2gis.ru/licensing-agreement) запрещает это прямо: п. 5.1.8 запрещает «любые автоматические и автоматизированные запросы», скрипты и ботов «для сбора, выгрузки и (или) передачи каких-либо данных», если это не разрешено соглашением; п. 5.1.4 и 5.2 запрещают извлечение и коммерческое использование справочных данных. **Использование парсера нарушает эти условия и остаётся на ответственности владельца проекта.** 2ГИС может заблокировать доступ и преследовать нарушение прав (п. 8.6, 8.7). Перед использованием стоит посоветоваться с юристом или запросить разрешение у 2ГИС.

**Что парсер делает и чего не делает:**
- Читает данные организаций из состояния самой страницы (`initialState`): сначала у страницы, затем из её текста. Ничего на странице не нажимает. Вёрстку не разбирает: только если состояния нет, берёт из ссылок `tel:`, `mailto:` и внешних ссылок. Такой способ не может сказать, что сайта нет, поэтому карточка без внешней ссылки считается нераспознанной.
- Берёт только данные организаций: название, адрес, телефоны, сайт, публичный email, координаты, ссылку на карточку. Рубрикой служит ниша из запроса. Отзывы и фото не собираются.
- Открывает одну страницу за раз со случайной паузой 3–8 секунд, не чаще одного сбора в сутки, с лимитом страниц и организаций за запуск.
- Соблюдает `robots.txt`: если страница запрещена или файл нельзя прочитать, парсер не начинает работу.
- Использует стандартный User-Agent браузера. Без окна в нём видно `HeadlessChrome`; при запуске с окном браузер сам подставляет свой обычный User-Agent.
- **Не решает капчу, не использует прокси, не подменяет отпечатки браузера и не обходит защиту.** Добавлять это нельзя.

**Что происходит при капче, ответах 401/403/429 или странице, пришедшей пустой:**
1. Парсер сразу останавливается, бот пишет в лог и сообщает администраторам. Найденное до этого сохраняется. Единственное исключение: при капче сборщик в режиме `--assisted` сначала ждёт человека, см. «Сбор с участием человека».
2. Следующая попытка не раньше чем через 6 часов, затем через 12.
3. После трёх блокировок подряд парсер отключается до команды `/provider_on 2gis_scraper`. Успешный запуск обнуляет счётчик; запуск, в котором капчу проходил человек, его не меняет.

Пока парсер на паузе или отключён, работают остальные источники из `COLLECT_PROVIDERS`.

**Что блокировкой не считается.** Счётчик блокировок и паузы не меняются, а интервал между запусками не занимается, если запуск не дал ничего, кроме:

- **Нераспознанного формата.** Страница загрузилась нормально, с заголовком и без отказа, а нужных данных в ней нет. Страница поиска останавливает сбор сразу, карточка пропускается, а после трёх карточек подряд сбор останавливается: «Формат страницы не распознан: нужна правка парсера, это не блокировка». Что делать: см. «Если формат страницы изменился».
- **Отсутствия связи.** Сайт не прислал ни одного ответа: DNS, таймаут, обрыв на `robots.txt`. `robots.txt` читается до 3 раз с паузами 5 и 15 секунд. Сообщение: «Нет связи с сайтом 2ГИС: проверьте сеть и VPN, это не засчитано как посещение».

Запуск, в котором удалось прочитать хотя бы одну страницу или карточку, появилась капча или сайт ответил ошибкой, интервал занимает. Прерванный вручную запуск тоже: сборщик не успел понять, что он дал.

Браузер закрывается после каждого запуска, в том числе при ошибке и остановке бота. При изменении сайта парсер потребует доработки: всё, что зависит от сайта, находится в `src/services/scraper/twogis_site.py`.

### Ключ 2ГИС

Основной источник лидов. Как получить ключ: создайте его в [кабинете Platform Manager](https://docs.2gis.com/platform-manager/subscription/keys), пропишите в `DGIS_API_KEY`, а дату создания в `DGIS_KEY_CREATED_AT`. Если ключа нет, бот работает как обычно: источник `2gis` пропускается, причина видна в логе и в `/collect_status`.

| Настройка | По умолчанию | Назначение |
|---|---|---|
| `DGIS_DEMO_KEY` | `true` | Ограничения демо-ключа: не больше 10 объектов на странице и 5 страниц на запрос. Значение `COLLECT_PAGE_SIZE` выше 10 снижается автоматически. `false` только для платного ключа |
| `DGIS_REQUEST_CONTACTS` | `false` | Запрашивать телефоны и сайты (`items.contact_groups`) |
| `DGIS_REQUEST_LIMIT` | `1000` | Сколько всего запросов можно потратить с одним ключом; `0` снимает ограничение |
| `DGIS_REQUEST_RESERVE` | `50` | Сбор и ручной поиск останавливаются за столько запросов до лимита |
| `DGIS_KEY_CREATED_AT` | не задан | Дата создания ключа `ГГГГ-ММ-ДД`, необязательна. Срок считается как 30 дней от неё |
| `DGIS_KEY_WARN_DAYS` | `5` | За сколько дней до окончания срока предупреждать администраторов (раз в день) |

**Лимиты демо-ключа** ([тарифы](https://docs.2gis.com/en/platform-manager/subscription/pricing)): действует месяц, создаётся один раз, всего 1000 запросов к Places API, 5 страниц по 10 объектов, контактов нет. Каждая страница и каждый повтор тратят квоту. Бот считает все запросы, в том числе повторы и ручной поиск, и хранит счётчик в базе, поэтому он переживает перезапуски. Для нового ключа счётчик начинается с нуля. Суточный и пошаговый лимиты (`COLLECT_MAX_REQUESTS_PER_DAY`, `COLLECT_MAX_REQUESTS_PER_RUN`) работают как раньше.

**Запросы не тратятся на повторы.** Для каждой пары «ниша × район» бот помнит, на какой странице остановился, и следующий сбор продолжает с неё. Пара, пройденная до последней страницы, не запрашивается `COLLECT_RECHECK_DAYS` дней (по умолчанию 30). При всех нишах и районах полный обход на демо-ключе занимает до 300 запросов (60 пар по 5 страниц). Когда он закончен, сбор через API не тратит запросов, а в отчёте написано «все запросы пройдены до конца». Ручной поиск всегда начинает с первой страницы и тратит до 5 запросов на нажатие.

**Один ключ в двух местах.** Счётчик хранится в базе того компьютера, где идут запросы: сервер и домашний сборщик не видят расход друг друга. Используйте ключ в одном месте или разделите лимит, например `DGIS_REQUEST_LIMIT=500` и там, и там.

Коды 401, 403 и 429 не повторяются. 401 и 403 отключают источник, 429 и исчерпанный лимит останавливают его до следующего сбора. Администраторам приходит одно сообщение на одну и ту же проблему. Временные ошибки (сеть, 5xx) повторяются до 3 раз с растущей паузой.

**Что делать, когда ключ закончился.** За `DGIS_KEY_WARN_DAYS` дней до срока бот предупреждает администраторов. Когда API ответит 401 или 403, источник отключится с понятным сообщением, а `/next_leads` продолжит выдавать накопленные лиды. Дальше есть два пути:

1. Новый ключ: укажите его в `DGIS_API_KEY`, дату в `DGIS_KEY_CREATED_AT` и перезапустите бота. Источник включится сам, счётчик начнётся заново. Демо-ключ создаётся один раз, поэтому новым будет ключ по подписке.
2. Контакты: [доступ к `items.contact_groups` покупается отдельно](https://docs.2gis.com/en/api/search/places/overview) через отдел продаж 2ГИС. После подключения задайте `DGIS_REQUEST_CONTACTS=true` и `DGIS_DEMO_KEY=false`: телефоны и сайты будут сохраняться автоматически, проверка сайта и скоринг заработают как раньше.

### Лиды без контактов

Демо-ключ не отдаёт контакты, поэтому по умолчанию (`LEADS_REQUIRE_CONTACT=false`) бот работает так:

- Организация из 2ГИС без телефона и сайта считается лидом и попадает в запас. Её статус сайта `unknown`: сайт мог бы быть, просто API о нём не сообщил. Поэтому карточка и текст КП не утверждают, что сайта нет.
- В API ссылки на карточку нет ([в ответе Places API такого поля нет](https://docs.2gis.com/en/api/search/places/reference/3.0/items)), бот строит её из `id` и города: `https://2gis.ru/spb/firm/<номер>`. Если `id` не числовой, лид сохраняется без ссылки, а в логе появляется предупреждение.
- В сообщении лида: название, рубрика, адрес, строка «📞 Телефон: смотри в карточке» и кнопка «🔎 Открыть в 2ГИС». Если телефон известен, он показан как обычно.
- Кнопка «✏️ Добавить телефон» (только у лидов без телефона и только для администраторов): бот просит ответить на его сообщение номером, проверяет формат, приводит номер к виду `+7XXXXXXXXXX`, сохраняет в лид и обновляет карточку. Вопрос живёт час; после перезапуска бота кнопку нужно нажать снова.
- Такие лиды имеют статус `unknown` и выдаются после лидов с вердиктом о сайте, см. «Нужен ли сайт». В карточке написано «🌐 Статус неизвестен», проверить можно кнопками под ней.
- Дубликаты определяются по идентификатору источника и по названию с адресом; телефон участвует, когда он есть.
- OSM в этом режиме не меняется: организация из OSM без контактов по-прежнему отбрасывается, потому что карточки с контактами за ней нет.

При `LEADS_REQUIRE_CONTACT=true` организации без контактов не сохраняются, в том числе при импорте файлов. Если контактов нет, администраторам придёт одно предупреждение. При `false` предупреждений нет, только строка в логе один раз за сбор.

### Нужен ли сайт

Бот не утверждает, что сайта нет, если этого не сказал источник или человек. Статус сайта у лида один из таких:

| Статус | Что значит | Что в карточке | Очередь выдачи |
|---|---|---|---|
| `dead_site` | Адрес указан, но сайт не открывается | «⚠️ не работает» | 1 |
| `social_only` | Вместо сайта соцсеть или страница записи | «📱 только соцсеть» | 1 |
| `no_site` | Источник не указывает сайт | «🌐 Сайта нет (по данным источника)» | 1 |
| `no_site`, вердикт человека | Проверено вручную | «✅ Сайта нет (проверено вручную)» | 1 |
| `site_not_found` | Автоматический поиск ничего не нашёл | «🌐 Сайт не найден в поиске» | 2 |
| `site_uncertain` | Есть кандидат, но он может быть чужим | «🌐 Возможно, сайт: example.ru, проверьте» | 3 |
| `unknown` | Никто не проверял, например демо-ключ 2ГИС | «🌐 Статус неизвестен» | 4 |
| `site_found` | Рабочий сайт известен | «🌐 Сайт есть» | не выдаётся |

Внутри очереди лиды идут по оценке, затем с контактами раньше, затем самые старые. У `no_site` из OSM уверенность низкая (`site_confidence=low`): там часто просто не заполнен тег `website`.

**Сейчас автоматического поиска сайта нет** (платные поисковые API отложены), поэтому `site_not_found` и `site_uncertain` никто не выставляет, а с демо-ключом 2ГИС почти все лиды будут `unknown`. В выдаче будут организации с сайтами, пока их не отметите вы или пока сайт не будет прочитан из карточки: см. «Узнать сайт из карточки 2ГИС».

У лида из карточки `site_source=2gis_card`: это не вердикт человека, кнопки по-прежнему работают и имеют приоритет. Если карточка прочитана, а сайта в ней нет, лид получает `no_site` с уверенностью `medium` и в карточке «🌐 В 2ГИС сайт не указан».

**Проверка в один клик.** Под карточкой есть кнопки, они видны всем в чате, но работают только у администраторов:

- «🌐 Сайт есть»: лид уходит из запаса и больше не выдаётся, повторный сбор его не вернёт. Если он уже у вас на руках, его результат контакта не меняется.
- «✅ Сайта нет»: подтверждённый лид, поднимается в первую очередь.
- «🔎 Проверить в Яндексе»: обычная ссылка на поиск по названию и адресу, запрос делаете вы, а не бот.
- «🔎 Открыть в 2ГИС» ведёт на карточку. Если лид без сайта или с неоткрывающимся сайтом пришёл без ссылки на 2ГИС, вместо неё будет «🔎 Найти в 2ГИС»: поиск по названию и адресу.

Вердикт можно исправить второй кнопкой, повторное нажатие той же ничего не меняет. На результат контакта («Написал», «Ответили» и другие) вердикт не влияет.

**Сети.** Организация с тремя и более адресами под одним нормализованным названием или из списка брендов (`src/services/chains.py`) не выдаётся. Запись остаётся в базе, чтобы филиалы считались и в следующих сборах. Названия, которые только описывают занятие («Шиномонтаж», «Салон красоты»), сетью не считаются. С демо-ключом 2ГИС на страницу приходит 10 организаций, поэтому настоящая сеть может не набрать три адреса: тогда помогает список брендов. Метка сама не снимается, её пересчитывает `/rescore`.

**Оценка** складывается из весов в начале `src/services/scorer.py`: за сайт `dead_site` 60, `social_only` 55, `no_site` 50, `site_not_found` 40, `site_uncertain` 35, `unknown` 30; мобильный телефон +25, другой +15, соцсети +10; нет контактов −35 (кроме неподтверждённых статусов); высокая маржа +10; `hotels` и `horeca` −10; два филиала −10. Лид с вердиктом сохраняется от 30 баллов, неподтверждённый при любой оценке.

## 🏠 Сбор на домашнем компьютере

    компьютер: collect_cli.py → exports/leads_*.json → файл боту или scp → сервер: импорт → «📦 Следующие 30»

Сборщик запускается на вашем компьютере и кладёт лиды в файл, а сервер их импортирует. Бот на сервере при этом сам ничего не собирает. По умолчанию сборщик работает через API 2ГИС (`COLLECTOR_PROVIDERS=2gis`, нужен `DGIS_API_KEY`), браузер ему для этого не нужен, и в конце запуска он показывает, сколько запросов к API осталось. Лиды без контактов проходят импорт так же, как и при сборе на сервере; если на сервере задан `LEADS_REQUIRE_CONTACT=true`, они будут отклонены.

Парсер (`COLLECTOR_PROVIDERS=2gis_scraper`) остаётся в коде и по умолчанию выключен.

> **Если включаете парсер, прочитайте раздел «Парсер 2ГИС: ограничения».** Перенос на домашний компьютер не отменяет условий 2ГИС: п. 5.1.8 лицензионного соглашения запрещает автоматизированный сбор, ответственность на владельце проекта, а блокироваться теперь будет ваш домашний IP. Домашний адрес тоже не гарантирует отсутствия капчи: при проверке 5 ноября 2026 с компьютера разработчика первый же запрос получил капчу, и данные страниц 2ГИС ни разу не проверялись на реальном ответе. Если сайт откажет, сборщик остановится и сообщит об этом.

На Linux и macOS всё то же самое, только пути `.venv/bin/python`.

### Запуск вручную

    .venv\Scripts\python collect_cli.py

| Запуск | Что делает |
|---|---|
| `collect_cli.py` | Собирает и пишет новые лиды в `exports/leads_ГГГГММДД_ЧЧММСС.json` |
| `collect_cli.py --no-export` | Только собирает |
| `collect_cli.py --export-only` | Только выгружает накопленное, браузер не запускается |
| `collect_cli.py --enable-provider 2gis` | Снимает автоотключение и паузу после блокировок (то же, что `/provider_on` у бота) |
| `collect_cli.py --assisted` | Парсер 2ГИС с видимым окном браузера, капчу проходит человек: см. «Сбор с участием человека» |
| `collect_cli.py --assisted --ignore-interval` | То же, но не дожидаясь интервала между запусками; работает и с `--enrich`: см. «Когда запускать решаете вы» |
| `collect_cli.py --assisted --check` | Проверяет парсер на одной странице поиска и одной карточке, ничего не сохраняя: см. «Проверка парсера на живой странице» |
| `collect_cli.py --assisted --enrich файл.json` | Читает карточки лидов из файла бота и пишет файл с результатом: см. «Узнать сайт из карточки 2ГИС» |
| `collect_cli.py --assisted --enrich-latest` | То же с самым свежим `enrich_request_*.json` из `exports` или папки «Загрузки» |
| `collect_cli.py --assisted --google --enrich файл.json` | Ищет сайт и контакты тех же лидов в Google: см. «Поиск сайта в Google» |

Каждый лид попадает в файл один раз. Сборщик хранит состояние в своей базе `data/collector.db`, в том числе счётчик блокировок и время паузы, и не трогает базу бота.

Код возврата: `0` выполнено, `1` ошибка, `2` источник отказал или ждёт после отказа, `130` прервано.

### Запуск по расписанию

Рекомендуемая частота: **раз в сутки**. Запускать чаще бессмысленно: сборщик не откроет сайт раньше, чем пройдёт `SCRAPER_MIN_HOURS_BETWEEN_RUNS` (20 часов). Исключение для запуска вручную см. в «Когда запускать решаете вы».

**Планировщик заданий Windows.** Создайте задание: триггер «Ежедневно», действие «Запуск программы», программа — полный путь к `run_collector.bat`. Или из командной строки:

В параметрах задания оставьте «Не запускать новый экземпляр». Скрипт дописывает вывод в `logs\collector.log`. Для запуска из консоли с выводом на экран есть `run_collector.ps1`:

    powershell -ExecutionPolicy Bypass -File .\run_collector.ps1

**Linux и macOS (cron):**

    0 9 * * * cd /путь/к/проекту && .venv/bin/python collect_cli.py >> logs/collector.log 2>&1

Создайте папку `logs` заранее.

### Что делать при капче

Без `--assisted` сборщик сам остановится, напишет «капча, повтор не раньше ...» и завершится с кодом `2`.

- **Подождите и не запускайте сбор повторно.** Паузы 6 и 12 часов сборщик выдерживает сам, ранний запуск просто ничего не сделает.
- После трёх блокировок подряд источник отключится. Включайте его командой `--enable-provider`, только если проблема решена.
- Не пытайтесь обойти защиту. Форма на странице капчи ведёт в поддержку 2ГИС: [help.2gis.ru/feedback](https://help.2gis.ru/feedback/). Законный путь получить данные — их платный API с контактами.

### Сбор с участием человека

Режим для парсера 2ГИС, когда вы сидите за компьютером. Сайт показывает капчу, сборщик останавливается, показывает окно браузера и ждёт, пока вы сами пройдёте проверку. Потом он продолжает сбор по обычным правилам. Программа не нажимает ничего на странице капчи, не распознаёт её и не скрывает, что браузером управляет автоматизация. На сервере режим не работает: бот настройку игнорирует.

Парсер должен быть включён: `COLLECTOR_PROVIDERS=2gis_scraper` в `.env`. Иначе сборщик сообщит об ошибке и завершится с кодом `1`. Браузер ставится один раз: `.venv\Scripts\python -m playwright install chromium`.

**Windows:**

    powershell -ExecutionPolicy Bypass -File .\run_collector.ps1 -Assisted

**macOS и Linux:**

    .venv/bin/python collect_cli.py --assisted

Запускайте вручную, не по расписанию: без человека у компьютера капча закончится блокировкой. По этой же причине не используйте `run_collector.bat`: он пишет вывод только в лог, и сообщения в консоли вы не увидите. `SCRAPER_ASSISTED=true` в `.env` включает режим при каждом запуске, поэтому удобнее указывать флаг.

**Когда откроется окно с капчей:**

1. Сборщик подаст звуковой сигнал, попробует вывести окно на передний план (Windows может только подсветить его на панели задач) и напишет: «Пройдите проверку в окне браузера, жду до 5 мин.».
2. Пройдите проверку в этом окне сами. Окно не закрывайте: закрытое окно считается непройденной капчей.
3. Сборщик сам заметит, что капчи больше нет, выдержит обычную паузу 3–8 секунд, откроет нужную страницу заново и продолжит. Ничего нажимать в консоли не нужно.

Cookies сохраняются в `data/browser_profile`, как в обычном браузере, и после пройденной проверки капчи может не быть какое-то время. Папка не попадает в git. В ней лежат личные данные браузера: не передавайте её другим. Не запускайте два сборщика одновременно: профиль может использовать только один браузер.

**Что считается блокировкой.** Сборщик останавливается и записывает блокировку по обычным правилам (пауза 6 и 12 часов, отключение после третьей подряд, код возврата `2`), если:

- капча не пройдена за `SCRAPER_ASSISTED_WAIT_MINUTES` минут или окно закрыто;
- капча появилась снова сразу после прохождения;
- за запуск капча появилась больше `SCRAPER_ASSISTED_MAX_CAPTCHAS` раз;
- сайт ответил 401/403/429 или страница пришла пустой. Человека в этих случаях сборщик не зовёт.

Пройденная капча счётчик блокировок не увеличивает и не обнуляет. Обнуляет его только запуск, в котором капчи не было вовсе.

**Ограничения:**

- Режим работает только при участии человека и только для небольших объёмов. За запуск не больше 60 организаций и 80 страниц, считая карточки: этого хватает на одну выдачу «Следующие 30» с запасом. `SCRAPER_MAX_RESULTS_PER_RUN` и `SCRAPER_MAX_PAGES_PER_RUN` могут снизить эти значения, но не поднять.
- Режим сам ничего не ослабляет: паузы 3–8 секунд, `robots.txt`, `SCRAPER_MIN_HOURS_BETWEEN_RUNS` (не чаще раза в 20 часов, если вы не решили иначе, см. ниже) и действующая пауза после блокировки работают как обычно. Если сборщик пишет, что источник на паузе, окно не откроется: подождите. Перезагрузка страницы после капчи тоже идёт в счёт лимита страниц.
- **Прохождение капчи вручную не отменяет условий 2ГИС.** Сбор данных парсером всё равно может нарушать п. 5.1.8 лицензионного соглашения, ответственность остаётся на владельце проекта, а блокироваться будет ваш домашний IP. Держите нагрузку низкой и не обходите этот режим частыми запусками. Законный путь получить данные в объёме — платный API.
- Формат страниц проверен на одном образце (см. «Парсер 2ГИС: ограничения»). Если он изменится, сборщик напишет «Формат страницы не распознан»: это не блокировка, но проходить капчу повторно бесполезно, нужно править `src/services/scraper/twogis_site.py`.

### Когда запускать решаете вы

По умолчанию сборщик не открывает сайт раньше, чем пройдёт `SCRAPER_MIN_HOURS_BETWEEN_RUNS` (20 часов) после прошлого запуска. Если он откажет, то напишет, когда можно запустить по интервалу, и как запустить сейчас. Есть два способа не ждать:

- **На один запуск:** флаг `--ignore-interval`, только вместе с `--assisted`. В лог попадёт предупреждение. Интервал считается уже от этого запуска, если сайт что-то ответил:

      .venv/bin/python collect_cli.py --assisted --enrich файл.json --ignore-interval
      .venv/bin/python collect_cli.py --assisted --ignore-interval

  На Windows вместо `.venv/bin/python` пишите `.venv\Scripts\python`.
- **Насовсем:** `SCRAPER_MIN_HOURS_BETWEEN_RUNS=0` в `.env`. Настройка действует и на бота, поэтому на сервере с включённым `2gis_scraper` её лучше не использовать.

Что при этом не меняется: паузы 3–8 секунд между страницами, лимит 30 карточек за `--enrich` и лимиты страниц, `robots.txt`, остановка при капче и ответах 401/403/429, паузы 6 и 12 часов, отключение после трёх блокировок подряд, лимит `--check`. **Флаг не снимает паузу после блокировки и отключение источника**, для этого остаётся `--enable-provider 2gis_scraper`. Запуск с флагом не обнуляет счётчик блокировок, даже если прошёл без капчи.

Частые запуски сильнее нагружают сайт и повышают риск блокировки домашнего IP, а условия 2ГИС остаются в силе (см. «Парсер 2ГИС: ограничения»).

### Проверка парсера на живой странице

Проверка показывает, понимает ли парсер сайт сейчас. Она открывает окно браузера, одну страницу поиска (первая ниша и первый район из настроек) и одну карточку. При капче ждёт вас, как в `--assisted`.

**Windows:**

    .venv\Scripts\python collect_cli.py --assisted --check

**macOS и Linux:**

    .venv/bin/python collect_cli.py --assisted --check

В консоли будет, что удалось распознать: название, адрес, телефоны, сайт, соцсети, ссылка, а для пустого поля причина. В `logs/scraper_check.json` остаются те же поля и структура всех ответов сайта: адрес без параметров, имена ключей и типы значений. Текстов из ответов, ключа и поисковых слов в описании структуры нет, ключи вида телефона или номера заменены на `<ключ>`. Значит, по разделу `pages` можно поправить `src/services/scraper/twogis_site.py`, не показывая никому данные организаций. В разделе `recognized` они есть, его показывать не нужно. В `inline_state_variables` перечислены имена переменных с данными в тексте страницы. В `page_state` для `initialState` и `__REACT_QUERY_STATE__` указаны пути ключей, типы, длины массивов и пути ключей вроде `contact_groups`, `phone`, `website` с числом вхождений, без значений. В `page_state_problems` указано, почему переменную не удалось прочитать.

Проверка ничего не пишет в базу сборщика и не создаёт файл выгрузки, не сбрасывает счётчик блокировок и не считается сбором, поэтому не мешает сбору и не зависит от `SCRAPER_MIN_HOURS_BETWEEN_RUNS`. Её собственные ограничения:

- не больше `SCRAPER_CHECK_MAX_PER_DAY` запусков за 24 часа (по умолчанию 3, максимум 10), считая каждый начатый; отказ из-за паузы и запуск без связи с сайтом не считаются;
- не больше 2 страниц за запуск. Если капча появилась на первой странице, перезагрузка займёт вторую, и карточка не откроется: запустите проверку ещё раз, cookies уже сохранены;
- работает пауза после блокировки и `robots.txt`. Непройденная капча или ответ 401/403/429 считаются обычной блокировкой, а нераспознанная страница нет: для этого проверка и нужна.

### Если формат страницы изменился

1. Снимите образец за один запуск, когда сидите за компьютером:

       .venv/bin/python collect_cli.py --assisted --check --save-sample

   На Windows: `.venv\Scripts\python collect_cli.py --assisted --check --save-sample`.
2. В `data/samples/` появятся HTML страницы поиска и карточки и значения их переменных состояния (`..._state.json`).
3. **Не передавайте эти файлы и не добавляйте их в git:** в них данные организаций, телефон и другие данные вашего аккаунта 2ГИС (`data.user`), служебные ключи страницы и данные авторов отзывов. Папка есть в `.gitignore` и `.dockerignore`. Для обсуждения формата подходит раздел `pages` из `logs/scraper_check.json`.
4. На сайт больше не ходите, правьте `read_search_state` и `read_card_state` в `src/services/scraper/twogis_site.py` по образцу. Для тестов нужна та же структура с вымышленными данными: `tests/fixtures/twogis_state_*.json`. Копии страниц в тесты не кладите.
5. Удалите образец, когда он больше не нужен.

Сейчас данные лежат так: организация в `initialState.data.entity.profile.<id>.data` в формате Catalog API, контакты в её `contact_groups`, список найденного в `initialState.data.search.pagination.<id поиска>.<страница>.data`. В списке поиска контактов нет, они есть только в карточке, и телефон в ней виден без клика.

### Узнать сайт из карточки 2ГИС

С демо-ключом лиды приходят без контактов и со статусом `unknown`. Этот порядок действий узнаёт телефон и сайт из карточки на вашем компьютере, капчу проходите вы.

1. В боте: `/export_unknown 30`. Бот пришлёт файл `enrich_request_....json`: невыданные лиды со ссылкой на карточку, без сетей, порядок см. в «Какие ниши проверять первыми». В нём только `source`, `source_id`, `source_url`, `name`, `district`, а для поиска в Google ещё публичный адрес организации `address` и ниша `category`. Телефонов, email и того, кто работал с лидом, в файле нет.
2. Скачайте файл на компьютер со сборщиком и запустите чтение карточек. Менять `COLLECTOR_PROVIDERS` не нужно.

   **Windows:**

       .venv\Scripts\python collect_cli.py --assisted --enrich C:\Users\Вы\Downloads\enrich_request_20261106_100000.json

   **macOS и Linux:**

       .venv/bin/python collect_cli.py --assisted --enrich ~/Downloads/enrich_request_20261106_100000.json

3. Откроется окно браузера, карточки пойдут по одной с паузой 3–8 секунд. При капче сборщик подаст сигнал: пройдите проверку в окне сами и не закрывайте его, дальше он продолжит сам (подробнее в «Сбор с участием человека»).
4. Отправьте боту файл `exports/enrich_ГГГГММДД_ЧЧММСС.json`, путь к нему будет в консоли. Можно и положить его в `data/inbox` на сервере.
5. Бот проверит найденные сайты и пришлёт итог: сколько записей в файле, обновлено, сайтов найдено, без сайта в карточке, не распознано, проигнорировано и почему. После счётчиков идёт список полезных лидов из этого файла, сначала без сайта, потом с неоткрывающимся сайтом: название, ниша, адрес, телефон, для второго случая адрес сайта и ссылка на 2ГИС. Длинный список приходит несколькими сообщениями. Эти лиды не помечаются выданными, они остаются в запасе и выдаются «Следующими 30» как обычно.

Если прервать чтение (Ctrl+C, блокировка, закрытое окно), всё уже прочитанное окажется в файле, его тоже можно отправить боту.

**Какие ниши проверять первыми.** Собираются все ниши, а порядок считается сам по уже проверенным лидам. У каждой ниши есть доля полезных: (без сайта + не открывается + 1) / (проверено + 2). У ниши, которую ещё не проверяли, она равна 50%, поэтому такие ниши тоже попадают в выгрузку. Таблицу показывает `/niches`.

- «Без сайта» здесь включает `no_site`, `site_not_found` и `social_only`: соцсеть вместо сайта для нас тот же клиент.
- «Проверено» не включает сети и `no_site` с низкой уверенностью: пустой тег в OSM о нише ничего не говорит. `site_uncertain` тоже не считается проверенным.

`/export_unknown [N]` идёт по нишам от большей доли к меньшей и берёт не больше 10 лидов из одной ниши, поэтому в файле может оказаться меньше N, бот об этом напишет. Не меньше 20% файла, если хватает лидов, занимают ниши, где проверено меньше 5 лидов, поровну от каждой. Эти лиды идут в начале файла: за запуск читается только 30 карточек. `/export_unknown 30 beauty` берёт только эту нишу, без лимита 10, можно указать ключ или название, а неизвестная ниша вернёт список доступных.

**Что ограничено.** За запуск открывается не больше 30 карточек, остальные записи файла пропускаются. Чтение считается запуском парсера: повторить его, как и обычный сбор, можно не раньше чем через `SCRAPER_MIN_HOURS_BETWEEN_RUNS` (20 часов) или сразу с `--ignore-interval`, а пауза после блокировки на него действует в любом случае. Лимиты и счётчик блокировок те же, что у сбора. Запуск без капчи обнуляет счётчик, запуск с пройденной капчей его не меняет. Три нераспознанные карточки подряд останавливают чтение с сообщением «Формат страницы не распознан: нужна правка парсера, это не блокировка»: остальные карточки нагружали бы сайт зря. Запустите `--check --save-sample` и поправьте код. Запуск, не прочитавший ни одной карточки из-за формата или связи, интервал не занимает. В базу бота сборщик не пишет, а в своей базе меняет только счётчики.

**Что бот делает с результатом.** Записи сопоставляются с лидами по `source` и `source_id`, новых лидов из такого файла не появляется.

| В записи | Что станет с лидом |
|---|---|
| Сайт открывается | `site_found`, уходит из выдачи |
| Сайт не открывается | `dead_site` |
| Соцсеть или агрегатор вместо сайта | `social_only` |
| Карточка прочитана, сайта нет | `no_site`, «В 2ГИС сайт не указан», даже если есть соцсети |
| `parsed: false` | Ничего не меняется, лид останется `unknown` |

Телефоны приводятся к обычному формату и добавляются к сохранённому, email записывается, только если его не было, оценка пересчитывается. Проигнорированы, с указанием причины в итоге, будут записи:

- о лидах, которых нет в базе;
- о лидах уже выданных, в работе или в отказе;
- о лидах с вашим вердиктом о сайте;
- старше уже применённых, например повторно отправленный файл;
- с телефоном, который уже есть у другого лида. Это дубликат, как при обычном импорте, лид остаётся без изменений;
- которые не прошли проверку: нет `parsed` или `fetched_at`, непригодный адрес сайта.

Лид с `parsed: false` или дубликатом по телефону остаётся `unknown` и может попасть в следующий запрос снова.

Файл проверяется так же, как обычная выгрузка: размер, число записей, версия. Контрольная сумма и `count` здесь обязательны. Форматы:

```json
{"schema_version": 1, "kind": "enrich_request", "exported_at": "2026-11-06T10:00:00+00:00", "count": 1,
 "checksum": "sha256 от списка records",
 "records": [{"source": "2gis", "source_id": "70000001_abc", "source_url": "https://2gis.ru/spb/firm/70000001",
              "name": "Улыбка, стоматология", "district": "Центральный",
              "address": "Невский проспект, 10", "category": "dentist_clinic"}]}
```

```json
{"schema_version": 1, "kind": "enrich_result", "exported_at": "2026-11-06T10:20:00+03:00", "count": 1,
 "checksum": "sha256 от списка records",
 "records": [{"source": "2gis", "source_id": "70000001_abc", "parsed": true, "phones": ["+78125550101"],
              "website": "https://smile.example", "socials": [], "email": null,
              "fetched_at": "2026-11-06T07:20:00+00:00"}]}
```

Сборщик открывает только ссылки вида `https://2gis.ru/<город>/firm/<номер>`, номер в которых совпадает с `source_id`. Другие записи файла запроса он пропускает.

**Условия 2ГИС.** Всё сказанное в «Парсер 2ГИС: ограничения» относится и к этим режимам: чтение карточек программой может нарушать п. 5.1.8 лицензионного соглашения, даже если капчу проходит человек, а нагрузка низкая. Ответственность остаётся на владельце проекта, а блокироваться будет ваш домашний IP. Держите объём небольшим и не запускайте чаще, чем разрешают лимиты. Законный путь получить контакты в объёме — платный API. Режимы работают только в сборщике на компьютере, на сервере их нет.

**Что считается нераспознанным.** Карточка без поля `contact_groups` и карточка, где сайт указан только ссылкой через 2ГИС без адреса рядом: сборщик не примет непонятный ответ за отсутствие сайта и не отправит боту ссылку на 2ГИС. Если настоящие карточки организаций без контактов не содержат этого поля, такие лиды останутся `unknown`.

### Поиск сайта в Google

Тот же файл `/export_unknown`, но вместо карточек 2ГИС сборщик ищет каждый лид в Google по строке «название адрес Санкт-Петербург» и смотрит только первые 5 результатов. Работает только на вашем компьютере, в видимом окне со своим профилем `data/google_profile`, не на сервере и не по расписанию.

    .venv/bin/python collect_cli.py --assisted --google --enrich ~/Downloads/enrich_request_20261107_100000.json
    .venv/bin/python collect_cli.py --assisted --google --enrich-latest

**Как выбирается сайт.** Первый результат, который не соцсеть и не каталог (2ГИС, Яндекс, Zoon, ПроДокторов, Avito, реестры и другие из `CATALOG_DOMAINS` в `src/services/checker.py`), а его домен или заголовок похож на название не меньше чем на `GOOGLE_NAME_MATCH_THRESHOLD` (по умолчанию 0,6). Сравниваются слова названия без формы собственности и общих слов ниши: у «Стоматология Улыбка» это «улыбка», и её ищут в заголовке и в домене латиницей (`ulybka-dent.ru`). Если заголовок похож на страницу каталога («отзывы», «рейтинг», «на карте»), считается только домен. Страницы ВКонтакте, Instagram, Telegram, WhatsApp и сервисов записи из первых 5 результатов с похожим названием сохраняются как соцсети.

**Что открывается на сайте.** Один обычный запрос главной страницы через httpx, если её разрешает `robots.txt` сайта, с таймаутом 20 секунд, не больше 2 МБ, без обхода защиты и только на публичные адреса. Из неё берутся телефоны, email и ссылки на ВКонтакте, Instagram, Telegram и WhatsApp. Открывается ли сайт, решает бот при импорте, как и для карточек.

**Файл результата.** `exports/google_enrich_ГГГГММДД_ЧЧММСС.json`, тот же `kind: enrich_result`, но `schema_version: 2` и в каждой записи `"found_by": "google"`. Бот до этой версии такой файл не примет и скажет «неизвестная версия схемы», а не запишет его как карточки: сначала обновите бота на сервере. Смешивать записи из карточек и из Google в одном файле нельзя, такой файл отклоняется целиком. Файлы 2ГИС остаются версии 1 и принимаются как раньше.

| Нашёл поиск | Что станет с лидом |
|---|---|
| Сайт, и он открывается | `site_found`, уходит из выдачи |
| Сайт, и он не открывается | `dead_site` |
| Только соцсети | `social_only`, ссылки в соцсетях лида |
| Ничего похожего | `site_not_found` с низкой уверенностью: «не найден в поиске», а не «сайта нет» |

У всех таких лидов источник статуса `google`, уверенность средняя. Если о сайте уже что-то известно (статус не `unknown`, `site_uncertain` или `site_not_found`), а поиск сайта не нашёл, запись игнорируется с причиной «о сайте уже известно больше, чем нашёл поиск». Остальные правила те же, что для карточек.

**Защиты.** Их не ослабить настройками:

- Не больше `GOOGLE_MAX_PER_RUN` лидов за запуск (по умолчанию 15, максимум 20) и `GOOGLE_MAX_PER_DAY` поисковых запросов за календарный день компьютера (по умолчанию 60). Счётчик дня хранится в `data/collector.db`.
- Между поисками случайная пауза 10–25 секунд, задана в коде. Одна вкладка, один запрос за раз.
- Браузер со своими настройками по умолчанию: без скрытия автоматизации, подмены user-agent, прокси и действий на странице.
- Интервал между запусками `GOOGLE_MIN_HOURS_BETWEEN_RUNS` (3 часа, 0 выключает) считается отдельно от 2ГИС, `--ignore-interval` действует и здесь.
- Капча, страница о необычном трафике, ответ 403 или 429 сразу останавливают поиск. Найденное сохраняется в файл, причина попадает в консоль и в `logs/collector_errors.log`. При капче сборщик подаёт сигнал и ждёт до `SCRAPER_ASSISTED_WAIT_MINUTES`, пока вы пройдёте её в окне, но поиск всё равно не продолжает: капча считается блокировкой с паузой `SCRAPER_BLOCK_BACKOFF_HOURS`, которая удваивается. После трёх блокировок подряд Google отключается до `collect_cli.py --enable-provider google`. Запуск без происшествий, без капчи и без `--ignore-interval` обнуляет счётчик.
- Страница согласия на cookies тоже останавливает поиск и ждёт вашего ответа в окне, но блокировкой не считается: запустите поиск ещё раз.
- Нераспознанная страница выдачи останавливает поиск с сообщением «Формат страницы не распознан: нужна правка парсера, это не блокировка». Лид, по которому не удалось прочитать выдачу, в файл не попадает, чтобы не выглядеть лидом без сайта.

**Условия Google.** Автоматические запросы к поиску нарушают условия использования Google, а его `robots.txt` запрещает `/search` всем роботам, этот режим его не соблюдает. Ответственность на владельце проекта, а блокироваться будет ваш домашний IP. Держите объём небольшим.

### Перенос файла на сервер

**Способ 1. Отправить файл боту** в личку или в группу. Принимаются только `.json` от администраторов из `ADMIN_TG_ID` и `ADMIN_TG_IDS`. При включённом privacy mode бот не видит файлы в группе, если это не ответ на его сообщение, поэтому проще отправить в личку.

**Способ 2. Скопировать в папку на сервере.** Бот проверяет её раз в `IMPORT_INBOX_INTERVAL_SECONDS` (5 минут) и берёт файлы, которые не менялись последние 30 секунд:

    scp exports\leads_20261105_090000.json user@server:/путь/к/проекту/data/inbox/

Обработанный файл переезжает в `data/inbox/done/`, а не прошедший проверку — в `data/inbox/failed/` вместе с файлом `.reason.txt` с причиной. В Docker папка находится в `./db/inbox`.

### Настройка сервера

    COLLECT_ENABLED=false
    LEADS_MIN_POOL=60

- Сервер не запускает сбор. `/collect_now` и кнопка «▶️ Запустить сбор» сообщают, что сбор идёт на внешнем сборщике.
- Когда новых лидов меньше `LEADS_MIN_POOL`, бот просит загрузить новый файл, не чаще раза в сутки.
- Итог импорта приходит в `NOTIFY_CHAT_IDS` и админам: сколько в файле, новых, дубликатов, отклонено и почему. `/collect_status` показывает последний импорт, сколько лидов пришло файлами и сколько в запасе.

Новый порт на сервере не открывается: файл приходит через Telegram или ваш SSH.

### Правила импорта

- Записи проходят те же проверки, что и обычный сбор: уникальность по источнику и его ID, телефону, названию и адресу, проверка сайта и оценка. Сайт сервер проверяет заново, поэтому импорт большого файла занимает несколько минут.
- Нужен телефон или сайт. Организации с рабочим сайтом не сохраняются.
- Лиды, уже известные боту (в том числе выданные и обработанные), не меняются. Повторная загрузка того же файла ничего не добавляет. Исключение одно: файл `kind: "enrich_result"` обновляет ещё не выданные лиды, см. «Узнать сайт из карточки 2ГИС».
- Плохая запись отклоняется с подсчётом причины, остальные импортируются. Файл целиком отклоняется, если он повреждён, больше `IMPORT_MAX_FILE_BYTES`, содержит больше `IMPORT_MAX_LEADS` записей, имеет другую версию схемы или контрольная сумма не совпала.

```json
{
  "schema_version": 1,
  "exported_at": "2026-11-05T09:00:00+03:00",
  "source_host": "HOME-PC",
  "count": 1,
  "checksum": "sha256 от списка leads",
  "leads": [{
    "source": "2gis", "source_id": "70000001", "name": "Улыбка, стоматология",
```

Только публичные данные организаций, без токенов и настроек. Обязательны `schema_version`, `leads`, а в записи `source`, `source_id`, `name`; `count` и `checksum` проверяются, если указаны. Город не сохраняется: бот работает с одним городом.

## 👥 Работа в группе

Бот может работать в группе: присылать туда итоги сбора и выдавать лиды прямо в чат. Личка при этом работает как раньше.

**Настройка:**
1. Создайте группу в Telegram (или возьмите существующую).
2. Добавьте в неё бота и разрешите ему писать сообщения, если в группе это ограничено.
3. Отправьте в группе `/chat_id` от имени администратора бота, он ответит ID чата. ID групп отрицательные, у супергрупп они начинаются с `-100`.
4. Укажите ID в `.env`, несколько групп через запятую, и перезапустите бота:

       NOTIFY_CHAT_IDS=-1001234567890,-1009876543210
       NOTIFY_ADMINS_PRIVATE=true

5. Отправьте в группе `/start`: появятся кнопки «📦 Следующие 30», «📊 Статистика», «🤖 Статус сбора», «▶️ Запустить сбор».

`NOTIFY_CHAT_IDS` отвечает только за уведомления. Кнопки и команды работают в любой группе, куда добавлен бот, но итог сбора приходит по этому списку, а не в чат, где сбор запустили. Поэтому группу, откуда запускаете сбор, тоже стоит указать здесь.

**Privacy mode отключать не нужно.** С включённым режимом (по умолчанию) бот видит команды, в том числе `/cmd@имя_бота`, и нажатия на кнопки под сообщениями, этого достаточно. Если в группе несколько ботов, пишите команды с именем бота: Telegram может не доставить `/cmd` без него. Отключить режим (@BotFather → `/setprivacy` → Disable, затем удалить бота из группы и добавить снова) нужно, только чтобы работал текстовый ввод «📦 Следующие 30», меню «📋 Новые лиды» и загрузка CSV в группе. Тогда бот будет получать все сообщения группы, но реагировать только на свои команды.

**Кто что может:**
- Управляют ботом только пользователи из `ADMIN_TG_ID` и `ADMIN_TG_IDS`, проверяется тот, кто нажал или написал. Быть администратором группы для этого не нужно и недостаточно.
- Остальные на нажатие кнопки получают всплывающее «⛔ Нет доступа», на команду — короткий ответ не чаще раза в 5 минут. Обычные сообщения бот не замечает.
- Администратор группы, включивший в Telegram режим «анонимно», для бота не определяется и получит отказ.

**Что важно знать:**
- **Контакты лидов видны всем участникам группы:** карточки уходят в тот чат, где нажата кнопка. Выдавайте лиды только в группе, где это допустимо.
- Telegram разрешает боту не больше 20 сообщений в минуту в группу, поэтому карточки идут с паузой 3,1 с, и пачка из 30 приходит примерно за полторы минуты. Пока пачка отправляется, новая в этом чате не начнётся. Из разных чатов лиды не пересекаются.
- На карточке видно, кто поставил статус: «✍️ Написал — @username». Кто и когда отметил, есть и в выгрузке CSV.
- Если группа стала супергруппой, у неё меняется ID. Бот заметит это при отправке, продолжит писать по новому ID до перезапуска и сообщит его в лог и в чат. Замените ID в `NOTIFY_CHAT_IDS`.
- Ошибка отправки в один чат не мешает остальным и не прерывает сбор.

## 📥 Формат CSV для ручного импорта
Бот поддерживает загрузку `.csv` файлов (разделитель `,` или `;`, кодировка `UTF-8` или `Windows-1251`, до 2000 записей — остальные бот пропустит и сообщит, сколько). Распознаются колонки:
- `name` / `Название` / `Имя`
- `category` / `Рубрика` / `Категория`
- `district` / `Район`
- `address` / `Адрес`
- `phone` / `Телефон` / `Телефоны`
- `website` / `Сайт` / `Web`
- `socials` / `ВК` / `VK` / `Telegram`
